# WITH_U 기업 탄소 관리 MVP

기업의 실제 입력 자료, 등록 장치의 관측값, 기존 수목 조사 산정 결과를 대시보드·크레딧 현황·환경 리포트에 연결하는 웹사이트입니다.

## 사용 순서

1. 상단 **기업 데이터 입력**에서 기업명과 사업장·보고 경계를 등록합니다.
2. 배출 자료를 직접 산정량(tCO₂e) 또는 활동량·배출계수 방식으로 입력합니다.
3. **저장 및 장치 연결**에서 기존 관리자 조회 토큰으로 등록 장치를 조회합니다.
4. 상단에서 기업, 실제 측정 장치, 보고 시작·종료일을 선택합니다.
5. 대시보드·리포트에서 해당 기간의 실제 입력 자료를 확인합니다.
6. 리포트의 **보고서 저장**으로 생성 당시 자료를 보관합니다.

입력 기록은 저장 버튼을 누르면 이 브라우저에 저장됩니다. 다른 컴퓨터에서는 JSON 백업을 가져오거나, 서버 저장 후 서버 기업을 불러와야 합니다. 운영자 연결 토큰은 메모리에만 유지하며 저장 파일·보고서에 넣지 않습니다.

## 데이터 모드

- 장치 미선택 또는 서버 등록 목록에 장치가 없는 경우: 명시적인 예시 모드.
- 등록 장치 선택: 실제 기업 입력·해당 장치 현장 조사·실제 센서 기록 사용.
- 실제 모드에서 자료 없음: `미입력` 또는 `미수집`. 0이나 예시로 대체하지 않습니다.
- 센서 인증·통신 오류: `조회 실패`. 실제 기업 자료는 유지합니다.
- 시뮬레이션 센서 기록은 실제 관측값으로 사용하지 않습니다.
- 기업 변경 시 장치를 다시 선택해야 합니다. 장치 목록은 마지막 서버 조회 기준이며, 재조회 결과 등록 목록에서 사라진 장치의 선택은 해제됩니다.

## 배출 자료

귀속일, Scope 1/2/3, 배출원, 입력 방식, 근거자료 참조를 기록합니다. 직접 입력은 tCO₂e를 저장합니다. 활동량 방식은 아래 식을 사용합니다.

`배출량(tCO₂e) = 활동량 × 배출계수(kgCO₂e/활동량 단위) ÷ 1,000`

계수 기본값을 임의로 제공하지 않습니다. 사용자는 적용 계수의 출처·연도와 활동량 단위를 입력합니다. 귀속일을 기준으로 기간 내 기록을 합산하며 기간별 자동 일할 배분은 하지 않습니다. 미입력 Scope는 배출량 0을 뜻하지 않습니다. 기록은 수정·삭제할 수 있습니다.

## 크레딧 자료

기록일, 입고/소각/이전, 등록부, 동일 크레딧의 일련번호, 수량, 근거 참조를 입력합니다. 같은 등록부·일련번호의 중복 입고와 과거 날짜의 보유량 초과 소각·이전을 차단합니다. 연결된 소각·이전 기록이 있으면 입고를 바로 삭제할 수 없습니다. 보유량은 보고 종료일 기준, 소각·이전량은 선택 기간 기준입니다. 외부 등록부와의 자동 연계·발행·증빙 검증은 없으며 사용자 등록 현황으로 표시합니다. 배출량과 크레딧은 자동 상계하지 않습니다.

## 장치·수목 자료

녹지 관리자의 GPS·위치 등록·위성영상 경계·주변 OSM 녹지 추산·센서 조회를 유지합니다. EC·pH는 기존 장치/API 확장 전까지 미수집입니다. 센서는 1분마다 측정하고 약 6시간마다 서버에 누적 전송하며 웹 화면 자동 조회는 6시간 주기입니다.

수목 자료는 관리자에서 **실제 현장 조사 자료**로 표시하여 브라우저에 저장한 뒤 기업 데이터 화면의 **선택 장치의 수목 조사 가져오기**로 기업에 연결합니다. 초안·화면 예시·이전 버전에서 출처 미확인 상태로 저장한 입력은 실제 자료로 가져오지 않습니다. 기업·장치·두 조사일별 자료를 보관하며 보고 종료일 이전의 최신 조사를 사용합니다. 다른 장치의 조사는 합산하지 않습니다.

수목 계산식(carbon-engine.js)은 유지합니다. 결과는 저장량과 조사 기간의 연평균 저장량 변화이며 보고 기간의 확정 흡수량이 아닙니다. 토양·녹지 면적 기반 탄소 산정, 자동 크레딧 발행은 이번 MVP에 추가하지 않았습니다.

## 리포트

현재 실제 입력 자료 또는 명시적인 예시 자료로 화면·DOC·CSV·인쇄/PDF를 생성합니다. DOC는 기존과 같이 Word에서 열 수 있는 HTML 문서이며 DOCX 형식은 아닙니다. 저장 보고서는 기업·기간·장치·원자료·센서 관측값을 생성 당시 상태로 보관합니다. 이후 기록을 바꿔도 저장본은 바뀌지 않습니다. 저장본 보기·내보내기·삭제를 지원합니다. 보고서에 배출 범위별 미입력 상태와 수목 조사 기간·단위를 별도로 표시합니다. 공식 검증·인증을 받은 ESG 보고서를 자동 작성하는 기능은 아닙니다.

## 서버 저장 활성화

Vercel에 이미 사용하는 아래 환경 변수가 필요합니다.

- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY` — 서버 전용, 브라우저에 노출하지 않음
- `WITHU_ADMIN_TOKEN` — 기존 관리자 조회 토큰
- `WITHU_ALLOWED_DEVICE_IDS` — 기존 장치 허용 목록, 미설정 기본값 `pi5-monitor-01`

Supabase SQL Editor에서 `sql/company_workspaces.sql`을 한 번 실행합니다. `company_workspaces` 테이블에 RLS를 적용하고 익명·일반 로그인 역할의 직접 접근을 차단합니다. 서버 API만 서비스 키로 읽고 저장합니다. 기존 장치·센서 테이블은 유지합니다. SQL 실행 전에도 브라우저 저장·JSON 백업은 작동하며 서버 오류를 별도로 표시합니다.

`/api/company-workspace`의 GET/PUT은 운영자 토큰 인증을 요구합니다. 서버 저장은 사용자가 명시적으로 실행합니다. 최초 저장은 INSERT로 기존 기업 덮어쓰기를 막고 갱신은 서버 버전을 비교하여 다른 창·컴퓨터의 변경을 덮어쓰지 않도록 합니다. 충돌 시 자료를 백업한 뒤 서버 기업을 다시 불러와 병합해야 합니다.

이 MVP는 **운영자가 여러 기업 자료를 관리하는 구조**입니다. 회사별 사용자 로그인, 고객별 서버 접근 권한·멤버십·승인 흐름을 제공하는 다중 고객 SaaS 인증은 아직 없습니다. 운영자 토큰은 일반 고객 계정의 대체재로 배포하지 않습니다.

MVP 한도: 브라우저 기업 20개, 기업당 배출 기록 200개·크레딧 기록 200개·수목 조사 50개·저장 보고서 10개, 서버 저장 및 JSON 가져오기 2 MB. 사용 한도를 초과하면 자동으로 기존 기록을 삭제하지 않고 오류를 표시합니다.

## 파일 및 검증

- `index.html`, `workspace.js`, `workspace.css`: 기업 입력·실제/예시 모드·화면 및 리포트
- `business-engine.js`: 검증·배출량·크레딧 잔량·기간 집계·저장본
- `api/company-workspace.js`: 운영자 인증·서버 저장/조회
- `admin.html`, `admin.js`: 기존 관리자와 실제 수목 자료 출처 표시
- `carbon-engine.js`: 변경하지 않은 기존 수목 산정 엔진
- `sql/company_workspaces.sql`: 서버 저장 테이블

`node --test business-engine.test.cjs api/company-workspace.test.cjs`

기존 관리자·녹지·수목·API 테스트도 유지합니다. 상위 프로젝트의 `tools/verify_company_workspace.cjs`는 설치된 Edge를 별도 프로필로 실행한 로컬 브라우저 회귀 검증입니다. 모든 측정·기업·서버 자료는 테스트용이며 실제 Supabase에 기록을 쓰지 않습니다.
